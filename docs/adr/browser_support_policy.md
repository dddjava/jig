# ブラウザサポートポリシー

## 状況 (Context)

JIG が生成する HTML は、静的テンプレート・JSON データ・クライアントサイド JS で構成され、図は Mermaid がブラウザ上で描画します。ブラウザごとの実装差が利用者の閲覧結果に影響するため、サポート範囲と検証方法を定めます。

- `file://` と HTTP(S) の両方で閲覧できることが利用形態の前提です。
- テンプレートは CSS と JavaScript の標準機能を利用し、外部ライブラリは CDN から読み込みます。
- jsdom はレイアウトや Mermaid の実描画を再現できないため、構造検証と実ブラウザ検証には異なる役割があります。

## 決定 (Decision)

1. **サポート対象は Chromium 系（Chrome・Edge）、Firefox、Safari の安定版最新 2 バージョン**とします。

2. **これより古いバージョンの下限は、テンプレートが使用する CSS/JS 機能から導かれるものとし、固定のバージョン一覧を維持しません**。独立した一覧は実装と乖離しやすいためです。

3. **新しい CSS/JS 機能を採用するときは、対応状況を確認し記録します**。下限が上がる場合はその旨を明記します。`docs/adr/css_cascade_layer_policy.md` の記述方法を先例とします。

4. **`file://` と `http(s)://` の両方で動作することを要件とします**。どちらか一方でしか動かない機能は採用しません。

5. **自動検証の対象は Chromium のみ**とします。Firefox と Safari は手動確認とします。三ブラウザを自動検証しても、対応状況の差は上記 2 の機能単位の確認で捉えられ、実行時間に見合わないためです。

6. **CDN から読み込む外部ライブラリはバージョンを固定し、テストで使用する版と生成 HTML が読み込む版を一致させます**。通常の CI はネットワークに依存させず、外部依存を固定・代替します。実 CDN との結線確認はリリース候補の検証に分離します。

## トレードオフ (Trade-Offs)

1. **メリット**
   - サポート範囲が実装と連動し、独立した一覧の保守が不要になります
   - 下限が上がる判断が、機能を採用する時点でレビューの対象になります
   - `file://` 要件が明文化され、ストレージ API 以外の判断にも適用できます
   - 自動検証を Chromium に絞ることで、PR のフィードバック時間を抑えられます

2. **デメリット**
   - 「対応ブラウザ一覧」を単独で提示できず、使用機能から導く必要があります
   - Firefox・Safari 固有の不具合は手動確認まで発見が遅れます
   - CDN 依存があるため、オフライン環境での閲覧を保証できません
   - 安定版最新 2 バージョンという定義は、利用者側の更新状況によっては実態と合いません

## 採用ガイドライン (Guidelines)

1. **新しい機能を使うとき**
   - CSS/JS の新しい機能を採用する前に、Chrome・Firefox・Safari の対応状況を確認します。
   - 実質的な下限を引き上げる場合、その機能を使う便益が下限の引き上げに見合うかを判断し、結論を記録します。
   - `file://` で動作しない API（ブラウザストレージ、`fetch` によるローカルファイル読み込みなど）は採用しません。

2. **検証するとき**
   - 表示規則・データ変換・イベント配線は jsdom で検証します。
   - CSS のレイアウト、Mermaid の実描画、スクロール挙動は jsdom で原理的に検証できないため、実ブラウザで確認します。
   - 実ブラウザ検証を自動化する場合は Chromium に限り、画面ごとに「ページが読み込める」「主要データが描画される」「主要導線が操作できる」を確認します。
   - 実ブラウザ検証の自動化は、jsdom で検証できない不具合を継続して検知する必要が生じた場合に検討します。

3. **外部ライブラリを更新するとき**
   - `templates/partials/cdn-scripts.html` のバージョンと、テストで使用する依存のバージョンを同時に更新します。
   - 更新後、Mermaid の描画と Markdown のサニタイズを実ブラウザで確認します。

## 結論 (Consequences)

- サポート範囲が実装から導かれるため、一覧と実装の乖離が起きません
- 下限の引き上げが、機能採用時の明示的な判断になります
- `file://` 要件がブラウザストレージ以外にも適用され、採用可否の基準が一貫します
- Firefox・Safari の自動検証を持たないため、これらに固有の不具合は利用者からの報告で見つかる可能性があります
